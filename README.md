# KwachaLink Backend

Node.js/Express REST API for the Malawi-focused KwachaLink currency-exchange connection marketplace. It uses Supabase Auth and PostgreSQL, validates input with Zod, enables Helmet/CORS/rate limiting, and keeps the existing GitHub Pages frontend separate.

## Status and important caveats

This is an implementation package, not a claim of live deployment. The project was generated without access to your private Supabase dashboard, live schema, or Render account. Before production, inspect the current schema with `supabase/inspect_schema.sql`, compare results with `docs/DATABASE_SCHEMA.md`, and apply migrations only after backup and review. Existing columns or policies may conflict with the assumptions documented here. No payment gateway is configured; membership requests remain pending until a trusted administrator activates them.

## Quick start

1. Install Node.js 20+.
2. Copy `.env.example` to `.env` and fill in the Supabase project URL and publishable/anon key.
3. Run `npm ci` then `npm start`.
4. Test `http://localhost:10000/health`.
5. Apply reviewed SQL migrations in order in Supabase SQL Editor. Do not run against production before inspection/backup.

## Authentication

Register/login/password reset are handled directly by Supabase Auth from the frontend using the publishable key. The frontend sends `Authorization: Bearer <access_token>` to protected API routes. The API verifies the token with Supabase Auth. Do not put `SUPABASE_SECRET_KEY` in browser code.

## Tests

Run `npm test`. These local tests cover health, safe 404s, missing-token rejection, and offer validation. They do not prove live Supabase compatibility, real account flows, RLS correctness, concurrency, or Render deployment; those require the manual/integration checks in the guides.

**Lockfile note:** This environment could not reach the npm registry, so the included lockfile is a minimal npm lock manifest, not a fully resolved transitive lock generated by a successful install. Render is configured with `npm install` to resolve dependencies. For reproducible builds, run `npm install` in an internet-connected Node 20 environment and commit the resulting full `package-lock.json`, then switch Render Build Command to `npm ci`.
